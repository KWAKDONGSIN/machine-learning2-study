fit에 연결하기 — 인자와 로그 읽기 ★★

콜백만 만들어서는 아무 일도 안 일어나요. fit의 callbacks=[…]에 리스트로 묶어 넘겨야 연결돼요. 콜백이 여러 개면 callbacks=[early_stop, reduce_lr, ckpt]처럼 쓰고, 순서는 상관없이 매 epoch 끝에 모두 불려요.

history = model.fit( x_trn, y_trn, validation_data=(x_val, y_val), epochs=20, batch_size=128, callbacks=[early_stop], verbose=1 )
인자의미
validation_data=(x_val, y_val)epoch이 끝날 때마다 검증 세트로 val_loss, val_accuracy를 계산해요. 이것을 주지 않으면 val_* 지표가 만들어지지 않아서, monitor='val_accuracy'인 EarlyStopping이 볼 대상이 없어요(경고만 뜨고 작동하지 못해요).
epochs=20최대 epoch 수예요. EarlyStopping이 먼저 멈출 수 있어요.
batch_size=128한 번에 128장으로 1회 갱신(= 1 step)해요.
callbacks=[early_stop]epoch이나 배치 경계마다 불리는 도우미들의 리스트예요.
verbose1은 진행 막대, 2는 epoch당 한 줄, 0은 조용히 해요.

학습 로그 한 줄은 이렇게 읽어요. Epoch 1/20은 "20 epoch 중 1번째"이고, 430/430은 이번 epoch의 step 진행도예요. 뒤에 accuracy, loss(학습 지표)와 val_accuracy, val_loss(검증 지표)가 따라 나와요. val_가 붙으면 검증 세트로 잰 값이에요.

fit이 돌려주는 history에는 epoch마다 모은 값이 리스트로 남아요. history.history['accuracy'], ['val_accuracy'], ['loss'], ['val_loss'] 네 개예요. 이것을 그리면 7장의 학습·검증 곡선이 돼요.

시험엔 이렇게 써요

fit에 validation_data를 전달하면 epoch마다 val_loss와 val_accuracy가 계산되고, callbacks=[early_stop]으로 콜백을 연결하면 EarlyStopping이 이 값을 보고 학습을 중단한다. epochs는 최대치이며 조기 종료가 먼저 발동하면 그보다 일찍 끝난다.

잠깐 확인 — validation_data 없이 monitor='val_loss'를 쓰면 어떻게 되나요?

val_loss가 계산되지 않아 EarlyStopping이 볼 지표가 없어요. 그래서 조기 종료가 작동하지 못해요.
