데이터 나누기와 데이터 누수 ★

모델의 점수를 믿으려면 학습에 쓰지 않은 데이터로 재야 해요. 그래서 데이터를 세 덩어리로 나눠요.

덩어리보통 비율하는 일비유
학습(train)70~80%모델의 w, b를 고치는 데 써요문제집
검증(validation)10~15%학습 중에 점수를 보며 설정(하이퍼파라미터)을 고르고 과적합을 감시해요모의고사
테스트(test)10~15%모든 결정이 끝난 뒤 딱 한 번 최종 점수를 재요수능

왜 나눌까요? 외운 문제를 다시 풀면 100점이 나오는 게 당연해서, 진짜 실력은 처음 보는 문제로만 알 수 있어요.

데이터 누수(data leakage)는 시험 문제 정보가 공부 과정에 새어 들어가는 일이에요. 가장 흔한 두 가지가 있어요.

  • 테스트 점수를 보고 모델을 다시 고치기를 반복하면, 테스트가 사실상 학습에 쓰인 셈이에요.
  • 데이터를 나누기 전에 전체 데이터의 평균·표준편차로 스케일링하면, 테스트 데이터의 정보가 학습에 섞여요.
시험엔 이렇게 써요

학습·검증·테스트로 나누는 이유는 학습에 쓰지 않은 데이터로 일반화 성능을 정직하게 평가하기 위해서이다. 테스트 세트는 최종 평가에 한 번만 사용해야 하며, 테스트 정보가 학습이나 전처리에 섞이면 데이터 누수가 된다.

잠깐 확인 — 테스트 점수가 낮아서 모델을 고치고 다시 테스트를 봤어요. 무엇이 문제일까요?

테스트를 보고 모델을 고쳤으니 테스트가 학습에 새어 든 것(데이터 누수)이에요. 고치는 일은 검증 세트로 하고, 테스트는 끝에 한 번만 써야 해요.

머신러닝2에서는 이렇게 이어져요

9장에서 validation_data가 있어야 val_loss가 계산되고, 그 값을 보고 EarlyStopping이 멈출 때를 정해요. 즉 검증 세트의 역할이 그대로 이어져요. 0장 연습 문제에도 "테스트를 보고 다시 튜닝하면 누수"가 나와요.
